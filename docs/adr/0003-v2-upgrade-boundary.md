# Aurorama 2.0 的产品与架构代际边界

**Status**: accepted (2026-11-02)

Aurorama 2.0 定义为正式 `2.0.0` 产品大版本，同时代表内部 V2 架构、模块边界和研发流程代际升级。2.0 允许大范围重构和用户可见行为变化，但现有正式版升级必须保留登录、下载、书签、阅读进度、歌单、播放进度、设置和本地媒体库等用户资产。

**Why**: 若把 2.0 只当版本号或 UI 改版，就无法支撑阅读器、音乐、下载、视频和服务器写能力的结构性调整；若以清库或破坏性迁移换取重构自由，则直接违反用户对升级连续性的要求。

**Consequences**:

- 需求门完成后仍需目标架构、数据迁移、依赖许可、技术 Spike 和 UX 方案门。
- 数据结构变化必须提供旧安装升级路径和可丢弃 profile 的验证方案。
- “迁移可回滚”指可丢弃 profile 上的升级验证、备份 / 恢复或经验证的兼容回退路径，不要求真实用户数据执行破坏性 down migration。
- 2.0 的发布候选必须覆盖真实覆盖升级，不能用新装替代。

**Alternatives considered**:

- 只做增量 1.5：无法承载整体架构与流程重构。
- 以内部重构版本交付但沿用低版本号：会混淆发布、兼容和回滚边界。
- 允许清库升级：不满足用户数据连续性，拒绝。
