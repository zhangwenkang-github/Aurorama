# V2 仅使用本地可观测性

**Status**: accepted (2026-11-02)

Aurorama 2.0 使用本地结构化日志、诊断指标和测试证据来支持排障与验收，不引入远程遥测、产品分析或自动崩溃上传。该边界保护用户服务器、媒体和播放数据，并避免为诊断便利提前引入外部服务、隐私政策变更和供应链依赖。

**Why**: 客户端连接用户自建 Jellyfin、保存播放与阅读状态并处理本地媒体；默认上传诊断数据会扩大敏感面。当前可复现报告、本地日志和自动化验证足以支撑开发期质量门。

**Consequences**:

- 现场问题主要依赖可复现步骤、本地脱敏证据和用户主动提供的信息。
- 本地日志必须排除令牌、完整服务器身份、媒体私密路径和用户内容。
- 删除或增加远程诊断能力属于新的产品、隐私和外部依赖决策，必须另开 ADR 并定义字段、开关、留存、告知和回滚。
