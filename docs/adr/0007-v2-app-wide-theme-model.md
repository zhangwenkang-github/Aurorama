# V2 采用全 App 主题与正交外观模型

**Status**: accepted (2026-11-02)

V2 的主题是覆盖全 App 的完整视觉身份，而不是页面局部换色。所有主题共享相同的信息架构、
核心导航、组件行为和交互语义，但可以改变中性色、强调色、字体表达、表面材质、形状语言和
动效强度。明暗外观、内容域语义、阅读器正文显示偏好和系统动态色分别是正交维度；阅读器只可
局部覆盖正文显示主题，页面外框仍服从 App 主题。系统动态色是从壁纸派生的独立主题，不得叠加
到 Prism、Lumen 或 Nocturne 等品牌主题上。

**Why**: 当前全局浅/深色、Material You、Lumen 页面皮肤、阅读器五主题和三域色互相覆盖，
导致从页面 A 进入页面 B 时设计语言、明暗和强调色突然变化。把 App 主题与外观、内容域和阅读
显示拆开，可保留现有品牌 DNA，同时让多主题切换具有统一语义和可验证边界。

**Consequences**:

- Prism、Lumen、Nocturne 保留为三个独立品牌主题，不再允许页面级任意换皮；主题家族另包含
  Monolith 品牌主题和独立的系统动态色主题，共 5 个。
- 所有品牌主题支持浅色、深色和跟随系统；系统动态色主题跟随壁纸色彩与系统明暗。
- 影视、音乐、书籍的内容域角色跨主题稳定，具体三域色组由每个主题拥有。
- 产品 UI 最多 MiSans + Literata 两族；主题通过字阶、字重和排版比例表达差异，阅读正文字体
  设置不计入产品 UI 字族。
- 每套主题选择一个基础圆角 8 / 12 / 16dp，并只允许同心派生；圆点、胶囊和圆形单独作为形状。
- 主题驱动的界面交互动效统一为 150–300ms；播放进度、歌词等连续内容运动不属于装饰性主题
  动效，并尊重减少动画。
- 触屏必须覆盖默认、按下、聚焦、禁用、加载、空和错误态；Hover 只在鼠标、触控板等指针环境
  生效。首屏允许媒体内容卡，但必须有单一主焦点，禁止仪表盘式卡片堆叠。
- 新装默认 Lumen + 跟随系统。主题选择使用大尺寸实时预览，偏好按设备本地保存并即时应用。
- 迁移保留当前明暗偏好；动态色用户进入系统动态色，其余旧用户进入 Lumen，不显示阻断式向导。
- 阅读显示主题独立保存；主题切换不重载页面、数据或滚动位置；Android 12 以下动态色入口禁用。
- 系统动态色使用动态 Primary / Secondary / Tertiary 分别表示影视 / 音乐 / 书籍，并沿用
  Prism 的字体比例、组件几何、基础圆角与克制动效。
- 主题预览使用内置原创演示内容；默认当前外观并支持就地明暗切换；新装阅读主题跟随系统。
- 用户只能选择五套策展主题和外观，不能任意修改主题 token 或创建自定义主题。
- 产品 UI 字重限定为 400 / 500 / 700；布局值使用 4 / 8 倍数，1–2dp 仅用于线条。
- success / warning / error / info 是独立语义状态角色，必须配图标或文字，不能当装饰色。
- `docs/UI_DESIGN_SYSTEM.md` 是设计规范权威，`CinefinTokens.kt` 是唯一代码 token 源；本波
  不覆盖冻结的 TV 工程。
- App Logo 是主重绘对象，界面图标系统也需重绘以提高亮度与辨识度；启动图标沿用 Logo 母题。
- 极光渐变和粒子仅进入 Logo / 图标资产及少量关键图标状态，不进入页面背景或普通界面图层。
- 实现前必须先产出主题风格帧和 G1 视觉稿；本地 HTML/SVG + 无头浏览器渲染路径可用时
  不安装外部设计 MCP。
- 界面减少与熟悉图标重复的可见文字；可操作图标仍必须保留不可见的可访问名称、角色和状态。
- 低频、抽象或危险操作不得仅凭图形猜测，需保留简短文本或确认；动效不能成为唯一信息通道。
- 主题选择必须作用于全 App 的同一视觉权威；普通页面不得嵌套另一套完整主题。
- 明暗模式与 App 主题相互独立；每个品牌主题均提供经过校准的浅色与深色变体。
- 系统动态色必须整屏一致，不能只替换 Material 色槽而让自定义语义色继续留在固定品牌色板。
- 阅读器可保留正文内容显示主题，但顶栏、导航、按钮和弹层仍服从 App 主题。
- 每个主题及其支持的外观必须共享同一质量门，包括 WCAG AA、焦点可见、状态可辨、减少动画
  以及手机 / 平板布局验证。
- 设计系统需要单一主题数据源和稳定的语义角色；原始色值、页面局部色板和组件直写色值不得
  形成第二权威。

**Alternatives considered**:

- 继续使用页面局部皮肤：会造成跨页主题突变，拒绝。
- 只提供颜色预设：无法解决材质、字体、形状和动效的不一致，拒绝。
- 每套主题重排导航和核心交互：认知与维护成本过高，拒绝。
- 把动态色作为叠加开关：会与固定语义色混用，拒绝。
