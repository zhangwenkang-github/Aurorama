# V2 服务器写测试的安全边界

**Status**: accepted (2026-11-02)

用户现有的 `jellyfins.zhangwenkang.com` 继续作为生产只读服务器。V2 的服务器写功能只允许针对用户另外提供的独立测试写入服务器执行；该测试服务器中的媒体可由生产数据硬链接或复制而来，允许修改和删除非敏感测试数据。服务器与代理凭据只从 `F:\Develop\codex_work\Documents\Codex\资源.txt` 读取，任何值都不得写入仓库、日志、证据、命令回显或长期记忆。

**Why**: 服务器写能力是 2.0 的核心变化，但“测试数据可修改”不等于生产服务器获得写授权。把测试写入环境和生产读取环境分离，才能在不污染真实用户状态的前提下验证播放、下载、收藏、进度和其他写操作。

**Consequences**:

- 每项写测试必须在任务卡中声明目标服务器、测试对象、允许动作、禁止动作、清理与原值恢复。
- 生产服务器仍禁止任何写、删除或可能产生服务端持久副作用的调用。
- 认证值只在进程内使用；报告和 fixture 只保留脱敏结构、哈希或位置。
- 若测试写入服务器不可用，服务器写需求可以保持 `BLOCKED_ENVIRONMENT`，不得回退到生产写。

**Alternatives considered**:

- 直接在生产服务器测试写操作：违反长期只读边界，拒绝。
- 只用 fake 或本地数据库证明服务器写能力：不能证明真实 Jellyfin 协议，拒绝。
- 把凭据复制到项目配置便于复用：扩大泄漏面，拒绝。
